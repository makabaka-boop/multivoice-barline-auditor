# 多声部排练谱 · 小节对齐核对台

离线纯前端核对工具：用**整数分数（bigint 分子/分母）**累计各声部起止位置，核对
**标称小节号**、拆分**跨小节事件**、检查**多声部结尾**是否齐在同一条完整小节线。
TypeScript + React + Vite，由 Docker Compose 运行 `web` 服务；无后端、无外部网络请求。

## 为什么不用小数

三连音时值（如四分三连音 = 1/6）在二进制浮点中无法精确表示：

```
0.1666… 连加 6 次 = 0.9999999999999999   // 小数累加：下一小节首拍被误归前一小节
```

本工具全部位置、差额、小节判定均经 `src/engine/fraction.ts` 的约分 `Fraction`
运算（附点 ×3/2、三连音 ×2/3），屏幕像素百分比只用于画图，**不参与任何判定**。
报告中所有数值都是字符串分子/分母，排练员可按有理数手工复算。

## 运行

```bash
docker compose up --build web
# 打开 http://localhost:5173
```

本地（Node 20）：

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # Vitest
npm run build      # 类型检查 + 生产构建到 dist/
```

## 录入约束

- 拍号：分子 2–12，分母 4 或 8；小节长度 = 分子/分母（全音符分数）。
- 声部 1–4 个；每声部 1–120 个顺序事件。
- 事件：唯一 `id`（自动生成、全谱唯一、不可手改）、标称小节号（≥1）、
  时值分母 1/2/4/8/16/32、附点与三连音两个布尔。
- 时值 = `1/分母`，附点 ×3/2，三连音 ×2/3（两者同时出现恰好抵消）。

## 核对规则

1. 每声部从 0 开始用分数首尾相接，事件起始位置取累计值。
2. 实际起始小节 = `floor(start / 小节长度) + 1`，与标称小节号逐事件核对。
3. 跨小节事件在实际小节线处切成显示片段（记录小节、起止、小节内偏移、长度），
   **每个片段保留原事件 id**。
4. **首个错误**：取所有不符事件中起点位置最小者；同起点按声部顺序、再按事件次序。
5. 结尾：取最长声部终点为参考；逐声部给出总时值、占据小节数、是否落在小节线、
   - 到自身下一小节线的精确差额；
   - 到共同结束位置的精确差额（标出“未补足”的声部与差额）。

   最长声部自身不在完整小节线上时，共同结束线标记为无效。
6. 页面显示的结论与「下载 JSON」引用**同一份 `AnalysisReport`**；
   JSON 内含原始 `input`，自包含、可重新喂给引擎复算。
7. 任何录入编辑都会把已显示的报告标记为「已失效」（旧结论置灰、下载禁用），
   重新点击「核对小节对齐」后才产生新结论。

## 目录

```
src/
  engine/
    fraction.ts        # bigint 整数分数：四则、floor/ceil、比较、序列化
    fraction.test.ts
    rhythm.ts          # 时值、累计、跨线拆分、小节核对、结尾对齐、报告
    rhythm.test.ts     # 附点/三连音/跨线拆分/多声部结尾/校验
  state/
    editor.ts          # 录入台 reducer、校验、ScoreSpec 导出
    editor.test.ts
  lib/
    demo.ts            # 空谱与内置示例（含一处人为错号与结尾缺口）
    format.ts          # 仅用于显示的拍点文本/百分比
    format.test.ts
  components/
    ScoreEditor.tsx    # 拍号、声部、事件录入
    Timeline.tsx       # 并列时间轴 + 小节网格 + 跨线片段
    ReportView.tsx     # 首个错误、结尾表、明细表
  App.tsx              # 状态编排：核对 / 失效标记 / 下载同一结果
```

内置示例（点「载入示例（含错误）」）：4/4 两声部，长笛 3 小节（含三连音、附点、
跨小节的附点二分），`fl-e7` 标称小节号故意写错；单簧管只到 1½，比共同结束线缺 3/2。
